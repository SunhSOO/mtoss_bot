## 1. Claude Design에 처음 입력할 마스터 지시문

아래 문단과 이 문서 전체를 Claude Design 프로젝트의 첫 입력으로 사용한다. 시스템 아키텍처 문서도 함께 업로드한다.

```text
업로드한 두 설계 문서를 바탕으로 한국어 시스템 트레이딩 운영 웹앱의 고해상도 UI 디자인과 클릭 가능한 프로토타입을 만들어줘.

이 제품은 2~10명의 내부 사용자가 MT5 FX·CFD 전략과 토스증권 국내·미국 주식 카피트레이딩을 운영하는 비공개 도구다. 일반 소비자용 투자 앱이 아니라 주문 안전성, 계좌 상태, 승인, 위험 한도, 감사 추적이 중심인 운영 콘솔로 디자인한다.

디자인 방향은 적응형 듀얼 테마다. 한국장 주간에는 라이트 테마, 미국장 야간에는 다크 테마를 편안하게 사용할 수 있어야 하며 두 테마의 정보 계층과 의미 색상은 동일해야 한다. 과도한 네온, 게임화, 수익 과장, 매매를 부추기는 표현은 사용하지 않는다.

먼저 디자인 토큰과 핵심 컴포넌트를 정리한 뒤, 아래 화면 명세에 따라 데스크톱 1440px 고해상도 화면을 만든다. 이후 태블릿 1024px과 모바일 390px의 핵심 모니터링·승인·긴급 정지 흐름을 만든다. 정상 상태뿐 아니라 로딩, 빈 화면, 연결 끊김, 오래된 데이터, 부분 체결, 거절, 권한 없음, 긴급 정지 상태를 모두 디자인한다.

프로토타입에는 다음 네 흐름이 클릭 가능해야 한다.
1) 토스 계좌 연결과 위험 한도 설정
2) 13F 리밸런싱 주문 검토와 수동 승인
3) MT5 노드 연결 끊김 감지와 해당 계좌 정지
4) 전체 긴급 정지와 별도 전량 청산 2단계 확인

실제 API 연결이나 실제 자격증명을 요구하지 말고 현실적인 한국어 샘플 데이터만 사용한다. 마지막에는 디자인 시스템, 페이지 목록, 컴포넌트 상태, 상호작용 메모를 포함한 Claude Code handoff bundle을 준비한다.
```

## 2. 제품 목적과 디자인 원칙

### 제품 목적

사용자가 몇 초 안에 다음 질문에 답할 수 있어야 한다.

1. 모든 계좌와 MT5 노드가 정상인가?
2. 지금 어떤 전략과 카피 소스가 주문을 만들고 있는가?
3. 승인해야 할 주문이 있는가?
4. 위험 한도에 가까운 계좌가 있는가?
5. 주문이 접수·부분 체결·거절 중 어디에 있는가?
6. 문제가 생겼을 때 어느 범위까지 안전하게 멈출 수 있는가?

### 디자인 원칙

- **안전 우선:** 수익보다 연결 상태, 위험, 승인, 주문 상태를 먼저 보여준다.
- **조용한 정상 상태:** 정상 상태는 차분하게, 사용자의 행동이 필요한 예외만 강하게 강조한다.
- **브로커 실제값 우선:** 예상값과 실제 체결·포지션 값을 시각적으로 구분한다.
- **점진적 상세:** 대시보드는 요약, 클릭 시 드로어·상세 페이지에서 계산 근거와 로그를 보여준다.
- **명확한 범위:** 모든 위험·정지·설정 제어에는 적용 범위가 사용자, 계좌, 전략, 신호원, 종목 중 무엇인지 표시한다.
- **색상만으로 전달 금지:** 상태는 색상과 함께 아이콘, 텍스트, 형태를 사용한다.
- **거래 유도 금지:** 축하 애니메이션, 불꽃 효과, 과도한 상승 색상, 충동적 매수 CTA를 사용하지 않는다.

## 3. 사용자와 권한

### 관리자

- 사용자 초대와 역할 관리
- Python 전략 버전 등록·배포
- 외부 Webhook 공급자와 13F 기관 관리
- 시스템 위험 한도와 전체 긴급 정지
- 전체 계좌 상태와 감사 기록 조회
- 브로커 비밀값 원문은 조회 불가

### 트레이더

- 자신의 토스 계좌와 MT5 노드 연결
- 제공된 전략 선택과 허용된 설정값 수정
- 리더·외부 신호·13F 구독
- 자동·조건부 자동·수동 승인 정책 설정
- 자신의 주문 승인·거절과 계좌 정지
- 자신의 계좌·주문·감사 기록 조회

### 조회 전용

- 허용된 사용자 또는 계좌의 상태, 주문, 성과 조회
- 설정 변경, 승인, 정지, 자격증명 작업 불가

화면에서 권한이 없는 기능은 단순히 비활성화하지 말고, 기본적으로 숨긴다. 사용자가 URL로 접근하면 권한 없음 화면과 돌아갈 위치를 제공한다.

## 4. 시각 디자인 시스템

### 전체 분위기

기관용 운영 콘솔처럼 신뢰감 있고 정돈되어야 하지만, 오래된 금융 터미널처럼 답답하거나 과도하게 조밀하지 않아야 한다. 카드 남용을 피하고 표, 구분선, 여백으로 정보 그룹을 만든다. 실시간 거래 제품처럼 보이되 네온 색상과 장식용 차트는 사용하지 않는다.

### 테마

라이트·다크 테마는 수동 전환과 운영체제 설정 연동을 모두 지원한다. 사용자 선택을 저장한다.

| 토큰 | 라이트 | 다크 | 용도 |
|---|---|---|---|
| `bg-canvas` | `#F4F6F8` | `#0F141A` | 전체 배경 |
| `bg-surface` | `#FFFFFF` | `#171D24` | 표·패널 |
| `bg-subtle` | `#EEF1F4` | `#202833` | 선택·보조 영역 |
| `text-primary` | `#17202A` | `#EEF2F6` | 제목·중요 값 |
| `text-secondary` | `#5E6B78` | `#A4AFBA` | 설명·메타데이터 |
| `border-default` | `#D7DEE5` | `#313B46` | 구분선 |
| `action-primary` | `#2563A6` | `#5A9BD8` | 주요 행동 |
| `status-ok` | `#237A5B` | `#45B58C` | 연결·정상 |
| `status-warning` | `#A86100` | `#E6A23C` | 지연·주의 |
| `status-critical` | `#B42318` | `#F97066` | 위험·중단·파괴 작업 |
| `financial-up` | `#D84343` | `#FF7A7A` | 한국식 상승·수익 |
| `financial-down` | `#2F6FD6` | `#72A5FF` | 한국식 하락·손실 |

`financial-up`과 `status-critical`은 모두 붉은 계열이므로 같은 영역에서는 반드시 `+`, `−`, 경고 아이콘, “수익”, “위험” 같은 텍스트를 함께 사용한다. 파괴 작업 버튼은 금융 수익 값과 동일한 스타일을 사용하지 않는다.

### 타이포그래피

- 한글: Pretendard Variable 우선, `system-ui`, `sans-serif` 대체
- 영문·숫자: Inter 또는 Pretendard
- 가격·수량·시간: tabular numerals
- 화면 제목: 24px / 700
- 섹션 제목: 18px / 650
- 본문: 14px / 400
- 표: 13px / 400
- 보조 정보: 12px / 400, 대비 기준 유지
- 최소 가시 글자 크기: 12px

숫자는 오른쪽 정렬한다. 통화 형식은 `₩12,450,000`, `$8,921.30`, 수익률은 `+1.24%`, 손실률은 `−0.82%`로 표시한다. 날짜는 `2026.08.18`, 시각은 `14:32:08 KST`처럼 시간대를 포함한다.

### 공간과 형태

- 4px 기반 spacing scale: 4, 8, 12, 16, 24, 32, 48
- 패널 radius: 8px
- 입력·버튼 높이: 기본 40px, 조밀한 표 도구 32px
- 데스크톱 좌측 내비게이션: 240px, 축소 시 72px
- 상단 바: 64px
- 콘텐츠 최대 폭: 화면 전체 사용, 좌우 24~32px 여백
- 그림자는 팝오버·모달에만 약하게 사용

### 아이콘과 상태

단순한 outline 아이콘을 사용한다. 상태 텍스트는 다음 어휘를 일관되게 사용한다.

- 정상, 주의, 작업 필요, 중단됨
- 연결됨, 연결 중, 연결 끊김, 인증 만료
- 실행 중, 승인 대기, 일시정지, 실패
- 생성, 접수, 부분 체결, 체결, 취소, 거절, 확인 필요

## 5. 전역 레이아웃

### 데스크톱 1440px

- 왼쪽: 제품명, 주요 메뉴, 하단 사용자·도움말·테마 전환
- 상단: 현재 사용자, 계좌 범위 선택, 시장 시각(KST/ET), 전체 시스템 상태
- 본문: 페이지 제목, 설명, 주요 행동, 필터, 콘텐츠
- 오른쪽 드로어: 주문·승인·정합성 이슈의 상세 확인에 사용

좌측 메뉴 순서:

1. 대시보드
2. 전략
3. 카피트레이딩
4. 승인함
5. 주문·포지션
6. 위험 설정
7. 연결
8. 감사 기록
9. 관리자

### 태블릿 1024px

좌측 내비게이션을 아이콘 중심 72px로 축소한다. 표의 부가 열은 상세 드로어로 이동한다. 대시보드 요약은 2열을 유지한다.

### 모바일 390px

모바일은 다음 기능에 집중한다.

- 계좌·노드 상태 확인
- 승인 요청 검토·승인·거절
- 전략·카피 소스 일시정지
- 계좌 및 전체 긴급 정지
- 최근 주문·알림 확인

관리자 전략 배포, 복잡한 위험 규칙 편집, 감사 로그 전체 분석은 데스크톱 전용이다. 모바일 하단 내비게이션은 `홈`, `승인`, `주문`, `더보기` 네 항목을 사용한다.

## 6. 공통 컴포넌트

### AppShell

좌측 내비게이션, 상단 시스템 상태, 콘텐츠 영역, 글로벌 알림, 상세 드로어를 포함한다. 전체 긴급 정지 상태에서는 모든 페이지 상단에 닫을 수 없는 critical banner를 표시한다.

### AccountScopePicker

`전체 내 계좌`, 특정 토스 계좌, 특정 MT5 계좌를 선택한다. 현재 화면의 모든 숫자와 행동 범위가 이 선택에 따라 달라진다는 점을 명확히 표시한다.

### StatusBadge

작은 점만 사용하지 않는다. 아이콘 + 텍스트 + 필요 시 마지막 확인 시간을 표시한다. 예: `연결됨 · 8초 전`, `데이터 지연 · 2분 전`.

### MetricSummary

카드 한 개에 라벨, 값, 단위, 기준 시각, 필요 시 한도 대비 진행률만 표시한다. 장식용 상승 화살표는 금지한다.

### DataTable

- 고정 헤더, 열 정렬, 밀도 전환
- 숫자 오른쪽 정렬
- 필터는 표 바로 위 한 줄에 배치
- 행 클릭 시 오른쪽 상세 드로어
- 선택 행이 없어도 핵심 행동을 찾을 수 있어야 함
- 빈 화면, 권한 없음, 데이터 지연 상태 포함

### OrderStatusTimeline

생성 → 승인 → 실행 대기 → 브로커 접수 → 부분 체결 → 체결의 시간을 세로 타임라인으로 표시한다. 취소·거절·확인 필요는 분기 상태로 보여준다.

### RiskUsageBar

현재값과 한도를 함께 표시한다. 70% 미만 정상, 70~90% 주의, 90% 이상 작업 필요는 시각적 예시이며 실제 임계값은 시스템 설정에서 읽는다. 색상 외에 텍스트와 패턴을 함께 사용한다.

### ApprovalCard

신호원, 계좌, 종목, 방향, 예상 수량·금액, 현재 가격, 유효시간, 위험검사 결과를 요약한다. `상세 검토`가 기본 행동이며 목록에서 즉시 승인하는 기능은 제공하지 않는다.

### CriticalActionDialog

계좌 정지, 전체 긴급 정지, 전량 청산에 사용한다. 적용 범위, 즉시 발생하는 일, 발생하지 않는 일을 명확히 구분한다. 전량 청산은 재인증 후 확인 문구 입력과 최종 확인이 필요하다.

### EmptyState와 ErrorState

단순한 빈 일러스트보다 다음 행동을 제시한다. 예: `연결된 계좌가 없습니다 → 토스 계좌 연결`, `MT5 노드가 30초 동안 응답하지 않았습니다 → 설치 상태 확인`.

## 7. 페이지별 상세 화면 명세

### 7.1 로그인·MFA

목적: 초대된 내부 사용자만 안전하게 접근한다.

- 중앙 정렬된 로그인 패널
- 이메일, 비밀번호, 로그인
- MFA 화면은 6자리 TOTP와 패스키 선택
- 마지막 로그인 기기·지역이 달라졌으면 안내
- 오류는 `인증 정보가 올바르지 않습니다`처럼 계정 존재 여부를 노출하지 않음
- 배경에 주식 차트나 수익 이미지를 사용하지 않음

### 7.2 첫 설정 온보딩

네 단계 stepper:

1. 계정 보안: MFA 등록
2. 거래 연결: 토스 또는 MT5 선택
3. 위험 한도: 투자금, 1회 주문, 종목 비중, 일일 손실, 최대 낙폭
4. 첫 운영 모드: 섀도 모드가 기본, 실거래는 비활성

각 단계는 저장 후 다시 돌아올 수 있다. 실거래 활성화 전에 필수 위험 한도가 빠졌으면 다음 단계로 갈 수 없다.

### 7.3 대시보드

상단 첫 줄:

- 전체 시스템 상태
- 연결 계좌 `정상/주의/중단`
- 승인 대기 건수
- 위험 한도 작업 필요 건수

두 번째 영역:

- 좌측 2/3: 계좌별 순자산과 일일 손익 추이. 예상값이 아닌 브로커 확인값임을 표기
- 우측 1/3: 계좌·MT5 노드 건강 상태 목록

세 번째 영역:

- 승인 대기 3건 미리보기
- 실행 중 전략·카피 소스
- 최근 주문·체결 활동
- 정합성 이슈와 알림

대시보드에는 매수·매도 버튼을 두지 않는다. 빈 상태에서는 계좌 연결과 섀도 모드 시작을 안내한다.

### 7.4 전략 목록

각 전략 행 또는 카드에 다음을 표시한다.

- 전략명과 버전
- 대상 시장·주기
- 실행 계좌 수
- 운영 모드: 섀도, 수동 승인, 자동
- 최근 실행 시각과 상태
- 최근 10거래일 오류 건수

주요 행동: `전략 설정`, `일시정지`. 관리자만 `새 버전 배포`를 본다.

### 7.5 전략 상세·설정

탭:

1. 개요: 설명, 버전, 대상 시장, 데이터 요구조건
2. 설정: JSON Schema에서 생성된 검증 입력 폼
3. 검증: 백테스트와 섀도 운영 결과
4. 실행 기록: 신호, 오류, 처리시간

저장 시 변경 전후 값을 보여주고 다음 봉부터 적용되는지 명시한다. 전략 버전 변경은 기존 포지션에 미치는 영향을 안내하고 재승인을 받는다.

### 7.6 카피트레이딩 허브

상단 세 탭:

- 리더 계좌
- 외부 신호
- 13F 기관

공통 항목:

- 소스 이름과 유형
- 마지막 정상 신호
- 연결 상태
- 구독 계좌
- 목표 투자 비중
- 승인 모드
- 현재 드리프트
- 실행·일시정지

#### 리더 계좌 상세

리더의 목표 포트폴리오와 내 계좌의 현재 비중을 나란히 비교한다. `리더 주문 수량`보다 `목표 비중 차이`를 핵심 정보로 보여준다.

#### 외부 신호 상세

공급자 상태, 마지막 Webhook, 서명 검증, 중복·만료 건수를 보여준다. 원본 페이로드는 관리자에게만 구조화된 읽기 전용 형태로 제공하며 비밀값을 숨긴다.

#### 13F 기관 상세

기관명, CIK, 보고 분기, 신고 접수일, 수정 신고 여부, `분기 말 기준이며 최대 45일 지연될 수 있음` 경고를 상단에 표시한다. 기관 목표 비중, 토스 거래 가능 종목, 제외·매핑 실패 종목을 분리한다.

### 7.7 승인함

목록 기본 정렬은 만료 임박 순이다. 필터는 계좌, 신호원, 시장, 상태다.

승인 상세 드로어:

- 신호원과 생성·만료 시각
- 대상 계좌와 종목
- 현재 보유량 → 목표 보유량
- 예상 주문 수량·금액·수수료
- 현재가와 신호 당시 가격의 차이
- 통과한 위험 규칙과 한도 사용률
- 주문 후 예상 포트폴리오
- 승인, 거절, 닫기

승인 버튼을 누르면 가격·계좌 상태를 재검사한다. 값이 바뀌면 `조건이 변경되었습니다` 화면으로 전환하고 새 값으로 다시 확인받는다.

### 7.8 주문·포지션

상단 탭: `주문`, `체결`, `포지션`, `정합성 이슈`.

주문 표 열:

- 시각, 계좌, 신호원, 종목
- 매수·매도
- 주문 수량, 체결 수량
- 평균 체결가
- 상태
- 브로커 요청 ID

주문 상세에는 OrderStatusTimeline, 위험검사, 승인자, 원본 신호, 실행 의도, 브로커 응답, 정합성 결과를 보여준다.

`UNKNOWN/확인 필요` 상태는 실패와 다르게 표현하며 `재주문` 버튼을 제공하지 않는다. 먼저 `브로커 상태 다시 확인`만 제공한다.

### 7.9 위험 설정

범위 선택: 시스템, 사용자, 계좌, 전략·신호원, 종목.

위험 규칙은 이름, 현재값, 한도, 상태, 적용 범위, 마지막 변경자를 한 행에 표시한다. 설정 폼에는 단위, 허용 범위, 현재 포지션에 미치는 영향을 표시한다.

위험 한도를 느슨하게 변경할 때는 재인증을 요구한다. 더 엄격하게 변경하는 것은 즉시 적용할 수 있다. 한도 변경 이력은 페이지 하단에 표시한다.

### 7.10 연결

#### 토스 계좌

- 계좌 별칭, 시장, 인증 상태, 마지막 동기화
- 자격증명 등록·교체
- 저장된 비밀값은 다시 표시하지 않음
- 연결 테스트 결과를 권한, 계좌 조회, 시세 조회, 주문 가능 정보로 나눠 표시

#### MT5 노드

- 설치 단계와 개인 node pairing code
- Windows 서비스, MT5 터미널, 계정 로그인, 시장 데이터, 주문 권한의 체크리스트
- heartbeat, 버전, 마지막 포지션 동기화
- 연결 끊김 시 해당 계좌 자동매매 정지 상태를 명확히 표시

### 7.11 감사 기록

필터: 사용자, 계좌, 전략, 신호, 주문, 행위, 기간.

각 행은 시각, 행위자, 행위, 대상, 결과, trace ID를 표시한다. 행 클릭 시 `신호 → 위험검사 → 승인 → 주문 → 체결` 관계를 시간순으로 보여준다. JSON 원문은 관리자만 접을 수 있는 읽기 전용 영역으로 본다.

### 7.12 관리자

탭:

- 사용자·역할
- 전략 배포
- 신호 공급자
- 13F 기관·CUSIP 매핑 검토
- 시스템 상태
- 전체 긴급 제어

일상적인 관리자 기능과 전체 긴급 정지는 같은 시각적 비중으로 섞지 않는다. 긴급 제어는 별도 구역과 명확한 경고 스타일을 사용한다.

## 8. 핵심 프로토타입 흐름

### 흐름 A: 토스 계좌 연결

`연결 페이지 → 토스 계좌 추가 → client ID/secret 입력 → 비밀값 저장 안내 → 연결 테스트 → 계좌 선택 → 필수 위험 한도 → 섀도 모드 활성화 → 완료`

연결 테스트 실패 시 인증 실패, 계좌 없음, 약관 미동의, 호출 제한을 구분한다.

### 흐름 B: 13F 리밸런싱 승인

`대시보드 승인 대기 → 13F 승인 상세 → 공시 지연 안내 → 기관 목표와 내 계좌 비교 → 제외 종목 확인 → 위험검사 → 승인 → 가격 재검사 → 주문 계획 생성 → 주문 상태 페이지`

### 흐름 C: MT5 노드 offline

`글로벌 알림 → 연결 페이지 → offline 노드 상세 → 마지막 heartbeat와 영향받는 전략 확인 → 계좌 주문 정지 확인 → 재연결 가이드 → heartbeat 복구 → 사용자가 자동매매 재개`

노드가 다시 연결되어도 자동으로 거래를 재개하지 않는다.

### 흐름 D: 전체 긴급 정지

`상단 시스템 상태 → 전체 긴급 정지 → 적용 범위와 동작 확인 → 재인증 → 실행 → 모든 페이지 critical banner → 미체결 취소 진행률 → 정지 완료`

별도의 `전량 청산`은 같은 화면에 있지만 시각적으로 분리한다.

`전량 청산 → 시장 폐장·유동성 위험 안내 → 대상 계좌 선택 → 예상 주문 검토 → 확인 문구 입력 → MFA/패스키 재인증 → 최종 실행 → 주문별 결과 추적`

## 9. 상태별 디자인 요구사항

각 주요 화면에는 아래 상태를 모두 만든다.

- 정상 데이터
- 최초 로딩 skeleton
- 데이터 없음
- 일부 데이터만 성공
- 권한 없음
- 서버 오류와 재시도
- 시장 데이터 지연
- 브로커 API 호출 제한
- 토스 인증 만료
- MT5 노드 offline
- 전략 오류로 해당 전략만 정지
- 긴급 정지 상태
- 주문 부분 체결
- 주문 거절
- 주문 결과 확인 필요
- 수동 거래로 인한 포지션 불일치

오류 메시지는 무엇이 일어났는지, 주문이 나갔는지, 사용자가 무엇을 해야 하는지를 세 문장 이내로 설명한다. 예: `주문 요청 후 응답을 받지 못했습니다. 같은 주문을 다시 보내지 않고 토스 주문 내역을 확인하고 있습니다. 확인될 때까지 이 계좌의 AAPL 주문이 일시정지됩니다.`

## 10. 차트와 데이터 시각화

- 순자산: 선 차트, 브로커 확인값과 기준 시각 표시
- 일일 손익: 0 기준선을 가진 선 또는 막대 차트
- 최대 낙폭: 별도 영역 차트
- 종목 비중: 가로 막대, 목표와 현재를 겹치지 않게 병렬 표시
- 위험 한도: 현재값/한도 진행 막대
- 주문 상태: 타임라인
- 계좌·노드 건강: 상태 행 목록

원형·도넛 차트는 종목이 5개 이하이고 정확한 비교가 중요하지 않을 때만 사용한다. 기본 포트폴리오 비중은 정렬된 가로 막대를 사용한다. 모든 차트는 축, 단위, 시간대, 데이터 기준 시각, 접근 가능한 요약을 가진다.

## 11. 상호작용과 모션

- 페이지 이동과 드로어: 150~200ms의 절제된 ease-out
- 상태 변경: 위치 이동 또는 색상 전환, 반복 애니메이션 금지
- 연결 중 표시: 작은 progress indicator와 마지막 시도 시각
- 긴급·위험 상태: 깜빡임 금지
- `prefers-reduced-motion` 지원
- 성공 toast는 4초 후 사라지지만 거절·확인 필요 알림은 사용자가 닫을 때까지 유지

## 12. 접근성

- WCAG 2.2 AA 대비
- 모든 기능 키보드 접근 가능
- 명확한 focus ring
- 표 머리글과 행 관계를 스크린리더가 이해 가능
- 상태와 손익을 색상만으로 구분하지 않음
- 모달 열림 시 focus trap, 닫힘 시 원래 위치로 복귀
- 파괴 작업은 Enter 한 번으로 실행되지 않음
- 모바일 touch target 최소 44×44px
- 한국어 문장 우선, 영문 코드와 브로커 상태는 보조로 표시

## 13. Claude Design 산출물 요구사항

Claude Design은 다음 산출물을 만든다.

1. 라이트·다크 디자인 토큰 페이지
2. 공통 컴포넌트와 모든 상태 variant
3. 데스크톱 1440px 핵심 페이지 12종
4. 태블릿 1024px 대시보드·승인·주문 화면
5. 모바일 390px 홈·승인·주문·긴급 정지 화면
6. 네 가지 핵심 사용자 흐름의 클릭 가능한 프로토타입
7. 로딩·빈 상태·오류·offline·긴급 정지 상태 모음
8. 컴포넌트 사용 규칙과 상호작용 메모
9. Claude Code용 handoff bundle
10. standalone HTML 또는 내보낼 수 있는 프로토타입

실제 서비스 로고가 없으므로 장식용 가상 로고를 만들지 않는다. `시스템 트레이딩 콘솔` 텍스트 워드마크를 사용하고, 향후 브랜드 시스템으로 교체하기 쉬운 구조를 유지한다.

## 14. 샘플 콘텐츠 원칙

현실적인 한국어 샘플 데이터를 사용하되 실제 계좌·자격증명처럼 보이는 값은 쓰지 않는다.

예시:

- 사용자: 김운영, 박트레이더
- 계좌 별칭: 국내주식 주계좌, 미국주식 장기계좌, MT5 FX 데모
- 전략: USDJPY 1분 추세, S&P 500 변동성 필터
- 리더: 내부 리더 A
- 외부 공급자: Signal Provider Demo
- 13F 기관: Berkshire Hathaway, Pershing Square
- 종목: 삼성전자, SK하이닉스, AAPL, MSFT, BRK.B
- 주문 상태: 부분 체결 3/5주, 확인 필요, 승인 만료 01:24

모든 화면에 같은 샘플 사용자를 유지하여 프로토타입 흐름이 이어지게 한다.

## 15. 최종 검수 기준

- 5초 안에 시스템·계좌·노드 건강 상태를 파악할 수 있다.
- 승인 요청에서 신호원, 대상 계좌, 예상 주문, 위험검사, 만료 시간을 한 화면에서 확인할 수 있다.
- `긴급 정지`가 포지션 자동 청산을 의미하지 않는다는 점이 명확하다.
- 전량 청산은 재인증과 2단계 확인 없이는 실행할 수 없다.
- `UNKNOWN/확인 필요` 주문에 재주문 버튼이 노출되지 않는다.
- 13F 화면에서 분기 기준·공시 지연을 놓칠 수 없다.
- MT5 offline과 토스 인증 만료가 다른 문제로 구분된다.
- 모바일에서도 승인과 긴급 정지를 안전하게 완료할 수 있다.
- 라이트·다크 테마에서 의미 색상과 정보 우선순위가 동일하다.
- 수익 강조보다 위험·연결·승인 상태가 먼저 보인다.
- 컴포넌트와 화면이 Claude Code handoff에 충분한 이름과 상태 정의를 가진다.

## 16. Claude Design 반복 작업 순서

1. 이 문서와 시스템 설계 문서를 업로드한다.
2. 마스터 지시문으로 디자인 시스템과 대시보드 1차안을 만든다.
3. 대시보드에서 정보 밀도, 색상, 라이트·다크 대응을 먼저 승인한다.
4. 공통 컴포넌트를 확정한다.
5. 승인함과 긴급 정지 흐름을 우선 프로토타이핑한다.
6. 전략·카피·주문·위험·연결·감사·관리자 화면을 확장한다.
7. 오류와 offline 상태를 추가한다.
8. 태블릿·모바일 화면을 만든다.
9. 네 가지 핵심 흐름을 처음부터 끝까지 클릭 검수한다.
10. handoff bundle과 standalone prototype을 내보낸다.
